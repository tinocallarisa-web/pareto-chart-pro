Quick Start

1. Add the visual to your report

In Power BI Desktop, go to the Visualizations pane → click the three dots → Get more visuals → search for Pareto Chart Pro.

2. Bind your data

Drag a category field (e.g. Customer, Product, SKU) into Entity and a numeric measure (e.g. Revenue, Quantity) into Value. The chart renders automatically with bars sorted from highest to lowest contribution and a cumulative line.

3. Interpret the chart

The left Y-axis shows each bin's share of the total. The right Y-axis shows the cumulative percentage. The default reference line marks the 80% threshold — the point where the top entities collectively reach 80% of the total value.

4. Use drilldown

Add a hierarchy field (e.g. Category > Subcategory > SKU) to the Entity well. Use the drill buttons in the visual header to navigate levels.

Accessibility

Keyboard navigation

The chart is a single Tab stop. Tab into it once and the arrow keys move between bins, so the chart never traps keyboard users the way a control with one stop per bar would.

KeyAction
TabMove focus into, or out of, the chart
← → ↑ ↓Move between bins
Home / EndFirst / last bin
Enter or SpaceSelect the focused bin and cross-filter
Ctrl / Cmd + EnterAdd the bin to the current selection
EscapeClear the selection
Shift+F10 or ContextMenuOpen the context menu

Screen readers and visual accessibility

  • The chart exposes role="listbox" and each bar role="option" with aria-selected kept in step with the actual selection.
  • Every bar carries a descriptive label — its position, the entity range it covers, its share of total value, the cumulative percentage and how many entities it holds — so the chart is readable without seeing it.
  • Tooltips open on keyboard focus, not only on hover. A tooltip that only appears under a mouse pointer is invisible to a keyboard user.
  • A visible focus ring marks the focused bar, with a dedicated high-contrast variant.
  • In Windows or Power BI high contrast mode, every element — bars, cumulative line, axes, dots and reference lines — switches to the system palette automatically.

Performance & scale

The visual ranks and bins in the browser, so what governs responsiveness is not the size of your model but how many entities end up behind a single bar. That number is entirely under your control: it is the total entity count multiplied by the bin size.

Entities per bar, and what it feels like

Entities behind one barImported modelLive connection
up to 5,000ImmediateComfortable
5,000 – 10,000FluidSlow but works
10,000 – 20,000Perceptible, still usableNot recommended
above 20,000Not usable — the visual declines to filter and tells you so

Every figure above was measured on a 500,000-entity model in Power BI Service with an integer key, varying bin size to vary entities per bar — on both an imported model and a live connection to a semantic model.

Live connections are the slower case, and the one that matters. With an imported model the filter resolves in local memory; over a live connection to a semantic model the query travels to the model and back. Since most enterprise reports run live, the visual's limit follows the live figure: 10,000 entities per bar. Text keys are heavier per value than integer keys, so with long text codes expect the comfortable ceiling to be lower still — bind a numeric key where you have one.

Choosing a bin size for your model

Clicking a bar asks Power BI to filter the rest of the report by every entity behind it. Power BI carries that as a list of values, and beyond roughly 20,000 the query it has to build becomes too large to run comfortably. So the rule is simply:

maximum bin size % = 1,000,000 ÷ number of entities

Entities in the modelLargest bin size that stays filterableBars
up to 50,00020% — no constraint5
100,00010%10
250,0004%25
500,0002%50
1,000,0001%100

A practical pattern for very large models: read the chart at a comfortable bin size, and drop to a smaller one when you actually want to click through to the detail.

Free tier note. The Free bin size is fixed at 20%, which means five bars. Above roughly 50,000 entities each bar exceeds what Power BI can cross-filter, and clicking a bar will decline instead of filtering. This is a platform limit on filter size, not a restriction we impose — but reducing the bin size is a Pro control, so cross-filtering very large models does require Pro.

Loading large models

In Power BI Service the visual streams data in segments and has been exercised at 500,000 entities with slicers re-ranking correctly. Power BI's own ceilings apply: 1,048,576 rows, and 100 MB of data, after which it stops sending more.

In Power BI Desktop segment streaming is unavailable and the visual stops at 30,000 rows. This is a Desktop platform behaviour, identical in Free and Pro.

Whenever Power BI stops short of the full set, the visual says so in an amber notice with the exact number of rows it received. A Pareto always spans 0–100%, so a chart built on partial data looks entirely normal — the notice is the only way to tell.

Keep the entity key narrow. An integer key costs far less than a long text code at every stage: less data to stream toward the 100 MB ceiling, and lighter filters when you click. If you have both, bind the numeric one.

FAQ

Why are my bars not sorted from highest to lowest?

The visual always sorts automatically — you do not need to sort your data beforehand. If bars seem unsorted, check that:

  • The Value field contains a numeric measure (not a text field or a calculated column).
  • The measure resolves to a positive number for each row. Rows with null or zero values may be ignored.
  • You are not applying a report-level sort that conflicts with the visual's internal sort.
How do I set the 80/20 threshold?

Line 1 is pre-configured to 80% by default. You can change it in Format Pane → Reference Lines → Line 1 threshold. Set the value to any cumulative percentage between 1 and 99. You can add a second line (e.g. 60%) and a third line at any value (Pro only).

I bought Pro, but the Pro settings still have no effect

License validation happens asynchronously after the visual first renders, so for a moment after opening a report the chart is drawn on the Free tier. Give it a second and it re-renders with your Pro settings applied. If it persists:

  • Make sure you are signed into Power BI with the Microsoft account that purchased the license.
  • Check that the license is active in My Account → Licenses in the Microsoft 365 admin center.
  • Try closing and reopening the report.
Why do I see "(Pro)" settings I cannot use?

Every setting in the format pane is listed for all users, and the ones included in the Pro plan carry (Pro) in their name — bin size, outlier exclusion, bar border, bar gap, value labels and the third reference line. They are shown rather than hidden so you can see what the plan includes before deciding.

If you change one without a licence, the chart keeps rendering the Free result and Power BI shows its own notification with a link to get a licence. Nothing is lost: your setting is stored and takes effect as soon as the licence is active.

How does drilldown work?

Add a hierarchy to the Entity field well (e.g. Product Category → Product Subcategory → SKU). The drill buttons appear in the visual header. Click the single arrow to drill down one level across all bins, or click a specific bar and use the fork arrow to drill into that selection. The Pareto recalculates automatically at each level.

Can I use conditional formatting (the fx button) on bar colors?

Yes, from version 1.3.0.0. In Format Pane → Pareto → Bar color, click the fx button for the rule-based dialog — gradient, rules or field value, the same as a native visual.

One thing to understand about the result: Power BI resolves the rule per entity, but a bar is a bin holding many entities. Each bar takes the color of its top-ranked entity, falling back to the first entity in the bin that the rule resolves. So with a gradient, a bar shows where its largest member sits on the scale, not the average of the bin.

If what you want is to color bars by their position in the Pareto rather than by a field, use Threshold Colors instead — see below. It is usually the more useful of the two.

How do Threshold Colors work, and how are they different from fx?

Format Pane → Threshold Colors colors each bar by where it falls relative to a cumulative percentage threshold — 80% by default. Bars within the threshold take one color, bars beyond it another, and the bin where the cumulative line actually crosses can be highlighted separately.

This answers the question a Pareto is usually asked: which share of entities is the vital few, and where exactly does the line cross? The fx dialog colors by a field value; Threshold Colors color by position in the distribution.

When both are on, Threshold Colors wins. The full precedence is: high contrast → IBCS Mode → Threshold Colors → fx rule → the constant Bar color.

The chart looks correct in Power BI Desktop but shows Free behavior in the Service

This is usually a license assignment issue. Make sure the Pro license is assigned to the user account that is viewing the report in Power BI Service, not only to the account that published it. License assignment is managed in the Microsoft 365 admin center.

What is the maximum number of data rows the visual supports?

It depends on where the report runs:

  • Power BI Service: the visual streams data in segments and supports 500,000+ entities. The first segment is 30,000 rows; further segments are fetched automatically.
  • Power BI Desktop: segment fetching is not available, so the visual is capped at 30,000 rows and shows a "Data limited to 30,000 rows" notice. This is a Power BI Desktop platform limitation, not a tier limit — the row cap is identical in Free and Pro.

Because entities are grouped into bins, size rarely hurts readability: 10,000 SKUs render as 5 bars at the Free 20% bin size, or 10 bars at a Pro 10% bin size. What size does affect is cross-filtering — see Performance & scale for how to choose a bin size for your model.

Does the visual support high contrast mode?

Yes. When Windows or Power BI high contrast mode is active, the visual automatically uses system foreground and background colors for all chart elements — bars, lines, axes, dots, and reference lines — to meet accessibility requirements.

Does the visual send my data anywhere?

No. All data processing happens locally inside Power BI. The only external network request is the license validation call to the Microsoft licensing API (IVisualLicenseManager) — this is the standard Power BI mechanism and shares no report data. See the Privacy Policy for full details.
